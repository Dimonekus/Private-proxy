# Безопасность и доверие

Этот документ объясняет, из чего состоит проект, что именно выполняется на вашем
компьютере и как самостоятельно убедиться, что бинарники не подменены.

## Коротко

- Собственный код приложения — C#/WPF, собирается из исходников в этом репозитории.
- Движок — **официальный** `winws.exe` из [bol-van/zapret](https://github.com/bol-van/zapret)
  (через [zapret-win-bundle](https://github.com/bol-van/zapret-win-bundle)).
- WinDivert — официальный драйвер из [basil00/WinDivert](https://github.com/basil00/WinDivert).
- Никаких исполняемых файлов в git нет: они скачиваются скриптом с **закреплённых
  коммитов** и проверяются по **SHA-256**.
- Приложение каждый раз при старте пересчитывает хэши и не запускает движок,
  если хотя бы один файл не совпал с манифестом.
- Нет телеметрии, автообновлений и скрытой сетевой активности. Единственные
  сетевые запросы — проверки доступности сайтов в «Тесте стратегий».

## Что именно запускается

| Процесс / файл | Кто запускает | Зачем |
|----------------|---------------|-------|
| `PrivateProxy.exe` | вы | UI, управление, трей |
| `engine\bin\winws.exe` | `PrivateProxy.exe` | перехват и модификация пакетов |
| `WinDivert64.sys` | ядро Windows (через `WinDivert.dll`) | драйвер перехвата пакетов |
| `schtasks.exe` | `PrivateProxy.exe` | создание задачи автозапуска |

`winws.exe` запускается **только** с аргументами из выбранной стратегии
(`data/strategies/*.json`). Приложение не скачивает и не исполняет команды из сети.

## Цепочка поставок

1. `engine/manifest.json` фиксирует для каждого файла:
   - URL на `raw.githubusercontent.com` с **конкретным коммитом** (не `master`, не `latest`);
   - ожидаемый размер;
   - SHA-256.
2. `scripts/fetch-engine.ps1` скачивает файл во временный `.part`, проверяет размер
   и SHA-256 и только потом перемещает на место. При несовпадении — удаляет и
   завершается с ошибкой.
3. `EngineLocator` при каждом запуске приложения заново считает SHA-256 и сравнивает
   с манифестом. Статус виден в UI («движок проверен» / «не прошёл проверку»).
4. `WinwsRunner` отказывается запускать `winws.exe`, если `EngineStatus.Verified == false`.

Закреплённые версии:

| Компонент | Репозиторий | Коммит |
|-----------|-------------|--------|
| zapret + WinDivert + Cygwin (`winws.exe`, `WinDivert.dll`, `WinDivert64.sys`, `cygwin1.dll`) | `bol-van/zapret-win-bundle` | `bb6a20af35ed74778eb669f5413990eb8209c711` |
| Шаблоны fake-пакетов (`*.bin`) | `Flowseal/zapret-discord-youtube` (1.10.4) | `176f56dc3f11ce5915c26abcdde903f93d835b64` |

## Проверить самостоятельно

### 1. Хэши файлов

```powershell
powershell -ExecutionPolicy Bypass -File scripts\fetch-engine.ps1 -VerifyOnly
```

Ожидаемый результат — девять строк `ok` и `ошибок 0`.

То же самое вручную:

```powershell
Get-FileHash engine\bin\* -Algorithm SHA256 | Format-Table Hash, Path
```

Сравните с полями `sha256` в `engine\manifest.json`.

### 2. Совпадение с официальным WinDivert

Драйвер `WinDivert64.sys` из бандла **побайтово совпадает** с драйвером из
официального релиза WinDivert 2.2.2:

```powershell
# Скачайте https://github.com/basil00/WinDivert/releases/download/v2.2.2/WinDivert-2.2.2-A.zip
# и сравните:
Get-FileHash .\WinDivert-2.2.2-A\x64\WinDivert64.sys -Algorithm SHA256
Get-FileHash .\engine\bin\WinDivert64.sys -Algorithm SHA256
```

`WinDivert.dll` из бандла отличается от релизного 2.2.2 всего двумя байтами в
PE-заголовке (флаг Control Flow Guard и контрольная сумма). Машинный код идентичен.

### 3. Цифровая подпись драйвера

```powershell
Get-AuthenticodeSignature engine\bin\WinDivert64.sys | Format-List Status, SignerCertificate
```

`Status` должен быть `Valid`. Остальные файлы (`winws.exe`, `cygwin1.dll`,
`WinDivert.dll`, `*.bin`) не подписаны — это нормально для open-source сборок;
их целостность подтверждается SHA-256 и закреплённым коммитом.

### 4. Сборка приложения из исходников

Не доверяете готовому `PrivateProxy.exe` — соберите сами:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

Скрипт использует только локальный .NET SDK и файлы репозитория. Никаких
`Invoke-Expression` или загрузки кода из сети при сборке нет.

## Антивирус и `RiskTool.WinDivert`

WinDivert — легитимный open-source драйвер, но по своей функции (перехват и
подмена пакетов) он похож на инструменты, которые используют вредоносные программы.
Поэтому антивирусы часто классифицируют его как:

- `RiskTool.WinDivert`
- `HackTool:Win64/WinDivert`
- `Program:Win32/Wacapew` (эвристика)

Это **ожидаемая** реакция, а не признак заражения. Что делать:

1. Не отключайте антивирус целиком.
2. Добавьте папку приложения (или конкретно `engine\bin`) в исключения.
3. Перед этим обязательно выполните `scripts\fetch-engine.ps1 -VerifyOnly` —
   хэши должны совпасть с манифестом.
4. Если хэши не совпали — не добавляйте ничего в исключения, удалите `engine\bin`
   и скачайте заново.

## Что приложение не делает

- Не отправляет статистику, не имеет встроенной аналитики и рекламы.
- Не проверяет обновления и не скачивает новые версии самостоятельно.
- Не изменяет системные файлы, hosts, DNS или настройки браузеров.
- Не устанавливает службу Windows (автозапуск — задача Планировщика).
- Не хранит пароли и не проксирует трафик: пакеты обрабатываются локально драйвером.

## Права администратора

Перехват пакетов через WinDivert невозможен без прав администратора. Приложение
запускается как `asInvoker` и повышает права только по явному действию пользователя
(«Запустить» / «Тест стратегий») либо через задачу автозапуска с уровнем `HIGHEST`.

`winws.exe` — дочерний процесс `PrivateProxy.exe` и наследует его права. Другие
процессы приложения не запускают.

## Остаточные риски

- **Доверие к автору zapret.** Мы проверяем целостность и происхождение, но не
  проводим полный аудит исходников `winws.exe`. Для максимальной гарантии можно
  собрать `winws` из исходников самостоятельно (см. ниже).
- **Компрометация GitHub-аккаунта.** Если злоумышленник получит доступ к
  репозиторию, он сможет изменить `engine/manifest.json` вместе с файлами.
  Защита — сверять хэши с официальным бандлом или собирать движок самому.
- **Драйвер уровня ядра.** Любая ошибка в WinDivert или `winws` теоретически может
  привести к синему экрану. Проект использует стабильный официальный релиз, а не
  самописный драйвер.

## Сборка движка из исходников (следующий шаг)

`winws` собирается из [bol-van/zapret](https://github.com/bol-van/zapret) в среде
Cygwin/MSYS2. Это позволит вообще исключить готовые бинарники из цепочки доверия.
Пока в проекте используется официальный бандл с закреплённым коммитом и SHA-256 —
это компромисс между воспроизводимостью и сложностью настройки сборочного окружения.
